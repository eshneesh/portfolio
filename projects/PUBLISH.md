# Загрузка в GitLab

Набор объединён в каталоге `projects/` текущего репозитория. Ниже — дополнительная инструкция для переноса отдельных проектов в самостоятельные GitLab-репозитории.

## Семь отдельных репозиториев

Для каждого проекта создайте пустой проект на выбранном GitLab. Удобные имена совпадают с именами папок. При создании не добавляйте README на сервере: он уже есть локально.

Распакуйте соответствующий архив, откройте терминал в его каталоге и подставьте URL именно вашего нового репозитория:

```sh
git init -b main
git add .
git diff --cached --stat
git commit -m "Add standalone portfolio demo"
git remote add origin REPOSITORY_URL_FROM_GITLAB
git push -u origin main
```

`REPOSITORY_URL_FROM_GITLAB` — заполнитель, не готовый адрес. Настройки подписи коммитов сохраняются такими, как настроены у вас; обходить их команды не предлагают.

Перед push просмотрите staged-файлы. В каждом проекте уже есть `.gitignore`, исключающий `build`, `.env`, SQLite-индексы, кэш Python и виртуальные окружения. Данные в `data`, `corpus` и `examples` являются синтетическими/авторскими демонстрационными фикстурами.

## CI

Каждый `.gitlab-ci.yml` запускает unit-тесты и CLI-пример на Python 3.12 без установки зависимостей. Для этого нужен доступный Docker runner и возможность получить официальный образ `python:3.12-slim`. CI-конфигурация подготовлена; фактический запуск на GitLab здесь не проверялся.

## Видимость и оформление

Выберите нужную видимость проекта. Для внешнего портфолио площадка и ссылки должны быть доступны рекрутеру. Добавьте описание из `PORTFOLIO.md` и темы: `python`, `analytics`, `sql`, `reporting` или `information-retrieval` по смыслу.

Лицензия распространения намеренно не назначена. Если хотите разрешить другим использование кода, выберите подходящую лицензию и добавьте её отдельно. В наборе нет перенесённого корпоративного или стороннего исходного кода.
