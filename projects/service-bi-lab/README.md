# Service BI Lab

SQL/BI-лаборатория для анализа вымышленного процесса обработки обращений. Самостоятельный демонстрационный проект: 120 синтетических событий, звезда SQLite, SQL с CTE и оконными функциями, заготовки Power Query и DAX.

## Запуск

Python 3.12+, внешних зависимостей нет:

```sh
python build.py
python -m unittest discover -s tests -v
```

В `build/` появятся `events.csv`, `service.sqlite`, `cohort_metrics.csv` и `daily_flow.csv`. Генератор использует фиксированный seed и календарь 2025 года. В примере 120 событий, 96 закрытых и 24 открытых. Другие источники не подключаются.

## Модель и определения

Зерно факта — одно обращение. Измерения: календарь, категория и канал. Дата открытия и дата закрытия играют разные роли.

- `cohort_metrics.sql`: январская когорта по дате открытия. SLA — закрытие за ≤48 календарных часов / закрытые обращения этой когорты. Открытые не включены в знаменатель, пустой знаменатель даёт NULL.
- `daily_flow.sql`: поступления по дате открытия, закрытия по дате закрытия, остаток очереди на конец дня и поступления за последние семь календарных дней. Календарь сплошной, поэтому окно из семи строк соответствует семи дням.
- Начальный остаток очереди равен нулю: генератор не создаёт события до начала календаря. Для реальных данных нужен подтверждённый начальный остаток.
- Потоки сначала агрегируются отдельно, затем соединяются: это предотвращает размножение строк при JOIN.
- Временные метки нормализуются в UTC, длительность — календарная, не рабочая.

## Сборка в Power BI

В `powerbi/` лежат исходники для ручной сборки, а не готовый PBIX/PBIT:

1. Выполните `python build.py`.
2. Создайте текстовый запрос `DataFolder` по образцу `DataFolder.m`, указав абсолютный путь к `build` этого проекта.
3. Создайте запросы `Events` и `Calendar` из соответствующих `.m` файлов.
4. Отметьте `Calendar` как таблицу дат. Создайте активную связь `Calendar[Date] → Events[OpenedDate]` и неактивную `Calendar[Date] → Events[ClosedDate]`, обе 1:* с односторонней фильтрацией.
5. Добавьте меры из `Measures.dax` по одной. Для SLA используйте формат процентов.
6. Соберите карточки количества событий и SLA, столбцы по категориям и график поступлений/закрытий по календарю.

SQL выполняется и проверяется в SQLite. **M/DAX не исполнялись в Power BI Desktop**: их необходимо проверить при сборке модели в своей версии Desktop. Скриншоты и готовый Power BI-файл не заявлены как выполненные результаты.

Тесты используют отдельную маленькую фикстуру для границы SLA, открытых обращений, пустой категории и семидневного окна; дополнительно сверяют генератор и отсутствие нарушений внешних ключей. Корпоративные модели, SQL-схемы, формулы и подключения не переносились.
